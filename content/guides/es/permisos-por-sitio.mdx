El consentimiento de conexión, las reglas de firma y los permisos de autenticación son controles distintos. Abre **Permisos** para la cuenta activa.

## Reglas globales y sitio actual

**Reglas globales** define valores predeterminados para sitios conectados y cuentas. **Reglas por sitio** abre la web de la pestaña actual, no una lista de sitios guardados. Visita una página web si la extensión te lo pide. El acceso Gestionar permisos del panel abre el mismo editor.

Reglas globales aparece antes que Reglas por sitio. **Añadir regla** está junto al nombre del sitio. El botón **Reglas globales** del pie abre los valores compartidos; allí, **Ir a las reglas del sitio actual** aparece debajo del contenido. Volver regresa a Permisos al entrar desde ese menú.

Las filas grises heredan las reglas globales visibles. Las coloreadas son excepciones para esa cuenta y web. Editar una heredada crea una excepción; **Usar valor heredado** la elimina. Las antiguas reglas compartidas se migran una sola vez; las decisiones distintas de un sitio se conservan como excepciones.

## Añadir, cambiar o restablecer

Usa **Añadir regla** para elegir una acción y **Permitir**, **Denegar** o **Preguntar**. La excepción por sitio sustituye al valor global de esa acción. Una denegación más amplia puede seguir afectando y debe modificarse por separado. Son reglas para leer la clave pública, firmar tipos de eventos y cifrar o descifrar mensajes; no conectan una web nueva ni sustituyen los permisos de backend o relay.

**Restablecer excepciones del sitio** pide confirmación y elimina las de esta cuenta y web sin salir del editor. Solo quedan las globales en gris. Eliminar una excepción puede volver a aplicar un permiso global. El restablecimiento de todas las excepciones de cuentas en Reglas globales también pide confirmación y conserva las globales. Ninguno elimina permisos de autenticación.

Si el sitio actual está rechazado, se abre su editor de duración: una semana, un mes, un año o para siempre. Quitar el rechazo permite que vuelva a preguntar; no conecta ni autoriza el sitio.

## Revisar solicitudes

**Aprobar una vez** y **Denegar** resuelven la solicitud actual; una vez no significa toda la sesión del navegador. Las flechas ofrecen decisiones recordadas. En grupos puedes seleccionar qué aprobar o denegar el grupo mostrado. No se incluyen automáticamente solicitudes nuevas ni sin seleccionar.

La revisión describe la acción y muestra el contenido de notas o una vista del evento compatible. El icono de código abre el evento completo. Los mensajes privados se agrupan por remitente cuando es posible. Pulsar el contenido difuminado lo revela localmente durante 30 segundos; no autoriza su entrega a la web.

## Backend, relay y pagos

**Autenticación predeterminada de backend** empieza desactivada por cuenta. Activada, permite NIP-98 a sitios conectados con el mismo origen HTTPS exacto o pares verificados del registro. Las denegaciones explícitas tienen prioridad. **Autenticación del backend** muestra el estado, el enlace a las reglas y los permisos explícitos. La política automática no añade filas. Consulta la [guía de backends](/guides/backend-authentication).

**Autenticación de relays** gestiona aplicaciones seleccionadas o todos los sitios conectados por relay y cuenta, separadamente de la configuración de lectura y escritura. Consulta la [guía de relays](/guides/relay-authentication).

Los pagos Lightning mantienen sus confirmaciones, límites y [ajustes automáticos](/guides/zapping-auto-approve). Permitir firmas Nostr no autoriza pagos ilimitados.
