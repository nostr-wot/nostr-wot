[Nostream 3.2.0](https://github.com/cameri/nostream/releases/tag/v3.2.0) добавляет два решения для операторов реле. Первое относится к эксплуатации: можно запустить два процесса за HAProxy и заменять их по одному. Второе относится к модерации: отчёты настроенных доверенных модераторов могут скрывать события из запросов. Релиз также исправляет запросы, которые могли молча пропускать события.

Это опубликованный релиз исходного кода, а не запуск нового проекта. Nostream существует с 2022 года и уже был включён в каталог. Версия 3.2.0 опубликована 3 октября 2026 года.

## Необязательная blue/green-схема

[PR #777](https://github.com/cameri/nostream/pull/777) добавляет отдельный стек Docker Compose с двумя реле, blue и green, за HAProxy. Прокси проверяет каждый процесс через /readyz. Если один backend перестаёт быть готовым, option redispatch может повторить подходящий запрос на другом.

Скрипт заменяет одно реле, ждёт готовности нового процесса и затем переходит ко второму. Стек также включает поток Redis, чтобы живые события доходили до WebSocket-клиентов обоих процессов. Прежняя схема с одним реле остаётся доступной.

Релиз называет этот путь обновлением без простоя, но PR фиксирует более узкий результат проверки. Конфигурация Compose и синтаксис HAProxy были проверены. Скрипт ещё не запускали на живом стеке с подключённым WebSocket-клиентом. Это документированный вариант, а не независимое доказательство сохранения каждого соединения при любом переключении.

## Отчёты могут влиять на запросы

[PR #788](https://github.com/cameri/nostream/pull/788) добавляет nip56.hideActionableReports. По умолчанию настройка выключена и работает только вместе с включённой поддержкой NIP-56.

Когда обе настройки активны, отчёт доверенного модератора может стать применимым. Отчёт о событии скрывает это событие из REQ и COUNT. Отчёт о публичном ключе скрывает события этого ключа. Раньше Nostream мог записать отчёт как применимый, не меняя данные для подписчиков.

Политика остаётся выбором оператора. [NIP-56](https://github.com/nostr-protocol/nips/blob/master/56.md) описывает события kind 1984 как субъективные сигналы и предупреждает, что автоматической модерацией реле можно манипулировать. Версия не определяет достоверность отчётов, не включает скрытие автоматически и не удаляет событие с других реле.

## Исправления тихих ошибок

[PR #792](https://github.com/cameri/nostream/pull/792) исправляет фильтры с несколькими именами тегов. Раньше все условия должны были совпасть с одной строкой базы данных. Теперь для каждого имени используется отдельный подзапрос EXISTS.

Исправление также оборачивает каждый фильтр перед UNION. Лимит первого фильтра больше не ограничивает весь запрос и не ломает COUNT. Другие изменения заставляют nostream info и nostream invite create явно завершаться с ошибкой при недоступной базе данных, а не зависать.

В этой проверке не запускалось производственное реле и не воспроизводилась нагрузка. Релиз даёт необязательную топологию, добровольное действие модерации и исправленные запросы. Внедрение и реальное поведение по-прежнему зависят от каждого оператора.
